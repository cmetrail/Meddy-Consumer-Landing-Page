# Performance changes

The page layout, CSS, animation durations, easing curves, models, lighting, and
scroll paths are preserved. Source artwork remains available.

## Assets

| Source | Original bytes | Generated bytes | Method |
| --- | ---: | ---: | --- |
| Homepage enrollment SVG | 31,862,264 | 3,218,360 | Preserve SVG markup; downsize embedded photos to at most 2048px and recompress JPEGs |
| Hero doctor | 976,621 | 459,528 | Lossless WebP |
| Hero nutrition | 572,150 | 365,750 | Lossless WebP |
| Hero runner | 442,495 | 273,770 | Lossless WebP |
| Hero sleep | 505,000 | 301,224 | Lossless WebP |
| Fitness measurable background | 18,420,422 | 11,596,522 | Lossless WebP |

These are source sizes, not measured browser transfer savings. Next.js still
resizes and encodes raster images through its image optimizer. The fitness crop
and its `sizes` values intentionally remain unchanged. Visible decoded pixels of
the five lossless conversions are checked against their original PNGs.

The enrollment SVG keeps its paths, text outlines, transforms, gradients, filters,
and dimensions. Its embedded photos are recompressed, rather than pixel-identical.
Render comparisons at 150px, 337px, and 674px verify unchanged alpha and a pixel
RMSE below 3 on a 0–255 scale. JPEG is retained for compatibility with SVG renderers.

Regenerate from the original files, using the Sharp version installed with Next:

```powershell
node scripts/optimize-performance-assets.mjs
node scripts/verify-performance-assets.mjs
```

## Animation work

- Decode the next hero image during the existing reading interval, without
  delaying or changing the five-second slide timer. Failed downloads remain
  nonfatal. Network delivery still depends on connection speed.
- Cache graph sizes, coordinate transforms, and the first eight binary-search
  steps on resize. Perform the remaining fourteen steps on the original SVG
  curves, retaining the previous 22-step precision. Models and rendering quality
  are unchanged.
- Batch image/font-triggered refreshes across the story hooks and smooth-scroll
  provider into one refresh per frame. Dispose queued work on route cleanup.
- Register the headless-compatible CustomEase plugin before creating its curve,
  including during server rendering.

Verify refresh batching and cleanup:

```powershell
node scripts/verify-scroll-refresh.mjs
```

## Production verification

```powershell
npm run build
node node_modules/next/dist/bin/next start -p 3100
```

The build requires Google Fonts access. Next.js compression and image optimization
remain enabled. Hosting/CDN settings have not been changed; validate response
compression, caching, asset failures, and cold-cache performance on the actual
deployment. Local checks cannot establish a production speedup or guarantee
frame rate on every device.
